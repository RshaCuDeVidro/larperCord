Escrevendo temas

Um tema do larperCord é um arquivo KDL que descreve a interface inteira: cores, fontes, estilos e a árvore de layout. Dá pra mudar a posição de tudo sem escrever uma linha de código.

Coloque o arquivo, por exemplo meu-tema.kdl, na sua pasta de temas:

SistemaPasta
Linux~/.config/larpercord/themes/ (ou $XDG_CONFIG_HOME/larpercord/themes/ quando essa variável existir)
Windows%APPDATA%\larpercord\themes\, normalmente C:\Users\<você>\AppData\Roaming\larpercord\themes\. Para abrir, cole %APPDATA%\larpercord na barra de endereço do Explorador de Arquivos

Também vale themes/, ao rodar de dentro do repositório. O app vigia as pastas de tema que existem quando ele abre. Se você acabou de criar a pasta, reinicie o larperCord uma vez: Configurações → Atualizações → Reiniciar o larperCord. Fechar a janela não conta, porque por padrão ela só esconde o app na bandeja. Daí em diante, ao salvar, o app recarrega na hora. Se houver um erro, aparece um aviso com arquivo:linha:coluna e o tema anterior continua valendo.

Salve o arquivo como UTF-8. No Windows, o "UTF-8" do Bloco de Notas está certo. Não use "UTF-16" ("Unicode"), que é também o que o > grava no Windows PowerShell 5.1: o tema não carrega e aparece um erro de sintaxe. "UTF-8 com BOM" (o que o Set-Content -Encoding UTF8 grava no Windows PowerShell 5.1) põe três bytes invisíveis no começo, e o app lê esses bytes como parte da primeira linha. Não faz mal quando o arquivo começa com um comentário, como os temas embutidos, mas se ele começar com theme, palette ou colors, essa linha é ignorada.

Troque de tema com F2, pela paleta (Ctrl+K → "tema: …") ou em Configurações → Aparência.

Prefere clicar a digitar? O criador de temas do site parte de qualquer tema embutido, edita cores, fontes e layout com prévia ao vivo, confere o contraste e entrega o .kdl. Ele também pega as cores de um tema do BetterDiscord ou do Vencord. Os temas que outras pessoas fizeram estão na galeria da comunidade, e Compartilhar seu tema explica como mandar o seu.

#Exemplo mínimo

kdl
theme "meu-tema" description="Servidores embaixo, chat em cima." preview=classic
palette "wal"                      // usa as cores do pywal (opcional)

colors {
    accent "wal:4"
    surface "mix(wal:0, black, 0.2)"
}

layout {
    column {
        row flex=1 {
            channel-list width=240 bg=sidebar
            column flex=1 {
                messages flex=1
                composer height=46 inset-x=16 inset-y=4
            }
        }
        guild-bar height=60 orientation=horizontal
    }
}

NóO que faz

styles { style "nome" … }estilos nomeados para usar com style=nome
layout { … }a árvore da interface (um único filho na raiz)

palette "wal" lê as 16 cores do pywal em ~/.cache/wal/colors (sempre dentro de $HOME, mesmo com XDG_CACHE_HOME definido). No Linux o app também vigia esse arquivo, então o tema acompanha o seu wallpaper. No Windows ele só procura lá quando a variável HOME existe (%HOME%\.cache\wal\colors; o pywal no Windows grava em %USERPROFILE%\.cache\wal). Lá ele não vigia o arquivo: as cores novas aparecem na próxima vez que um arquivo de tema for salvo ou o app abrir. Sem o arquivo, vale a paleta padrão. Para criar o HOME no Windows, no PowerShell: [Environment]::SetEnvironmentVariable('HOME', $env:USERPROFILE, 'User'). Depois feche o larperCord (Sair no menu do ícone da bandeja) e abra de novo pelo menu Iniciar.

"lighten(a, 0.1)"  "darken(a, 0.2)"
white  black  transparent

Tokens: bg rail sidebar surface elevated overlay text muted faint accent accent-text border hover selected online idle dnd danger mention link code-bg bubble-self bubble-self-text bubble-other shadow.

#Estilos

kdl
styles {
    style "card" bg="@surface" radius=18 border="@border" border-width=1.5 glow="@accent" shadow=16
}

glow é a cor da borda quando o mouse está em cima. shadow é o tamanho da sombra. Para um fundo simples, sem estilo nomeado, use direto no nó: bg=sidebar radius=12 (bg no nó também aceita expressão: bg="alpha(@accent, 0.4)").

Além disso, estilos e nós do layout podem ter as primitivas da seção Além do retângulo chapado: gradiente, padrão, grão, vinheta, sombra interna, borda por lado.

#Layout

Contêineres: row (horizontal), column (vertical), stack (um sobre o outro).

PropriedadeEfeito

inset-x= inset-y=margem interna de um componente
max-width=limita a largura e centraliza
hide-below=esconde quando a janela é mais estreita que isso
hide-below-height=esconde quando a janela é mais baixa que isso

O filho de uma row que tem width= fixo e contém channel-list ou member-list é ajustável: o app desenha uma alça de arrastar do lado que dá para o vizinho flex da row, e a largura escolhida pela pessoa soma com a que você definiu. Sem vizinho flex, não tem alça.

#Fontes no Windows

O Windows não tem fontconfig, então o nome da família funciona de outro jeito. O app só procura em C:\Windows\Fonts:

  1. Primeiro, um arquivo com o nome da família em minúsculas, sem espaços, terminando em .ttf: Segoe UI → segoeui.ttf, Georgia → georgia.ttf, Cascadia Code → cascadiacode.ttf (Windows 11). Esse arquivo vale para todos os pesos, então negrito e itálico saem iguais ao normal.
  2. Senão, a fonte do sistema do mesmo tipo, com negrito e itálico de verdade. Nomes com mono, code, consol, courier ou term viram Consolas (ou Courier New). Nomes com serif, georgia, times, garamond ou playfair, e sem sans, viram Georgia (ou Times New Roman). DejaVu Sans e DejaVu Sans Mono viram Segoe UI Symbol. O resto vira Segoe UI (ou Arial, depois Tahoma). O emoji vem da Segoe UI Emoji.

Por isso as fontes padrão, Inter e JetBrains Mono, aparecem como Segoe UI e Consolas, e font="Liberation Serif" aparece como Georgia. Instalar uma fonte normalmente não muda isso. Os arquivos de fonte têm nomes como JetBrainsMono-Regular.ttf, e fontes instaladas só para o seu usuário (o padrão do Windows, em %LOCALAPPDATA%\Microsoft\Windows\Fonts) não são procuradas. Para um tema que fique bem nos dois sistemas, use nomes de fonte que digam o que elas são (com Mono ou Serif no nome) e confira o tema com Segoe UI, Consolas e Georgia.

#A tela da call

Clicar num canal de voz troca a conversa por uma grade com um quadro por pessoa, desenhada pelo componente messages, então ela segue o tema:

PropriedadeEfeito
call-style="card"um estilo nomeado para cada quadro: fundo, gradiente, borda, sombra, brilho, reflexo, grão. Sem ele, o quadro usa elevated com uma borda fina de border
call-tint=0.22quanto da cor da foto de cada pessoa entra no fundo do quadro, de 0 (só o tema) a 1
avatar=o formato das fotos nos quadros, o mesmo das mensagens (none vira círculo ali)

O nome e a atividade usam text, e trocam por branco ou quase preto quando a cor da foto deixa o text difícil de ler. O anel de quem fala usa online, e a barra de botões da call usa bg, elevated, border e os cantos do tema. Com variant=irc, a call vira uma lista em texto. Exemplo do vidro.kdl:

kdl
messages flex=1 avatar=squircle call-style=card call-tint=0.16

#Além do retângulo chapado

Tudo aqui é opcional, vale num style "…" ou direto num nó do layout, e as cores são expressões ("alpha(@accent, 0.4)", ou só o nome do token). Elas são avaliadas com os tokens do momento, então acompanham o modo claro/escuro, a cor de destaque escolhida e os c-… do pedaço do layout.

kdl
styles {
    style "painel" radius=10 \
        gradient="alpha(@elevated, 0.9) alpha(@surface, 0.75)" gradient-angle=90 \
        pattern=dots pattern-color="alpha(@text, 0.05)" pattern-size=16 pattern-width=1 \
        grain="alpha(@text, 0.04)" vignette="alpha(black, 0.3)" vignette-size=0.55 \
        inner-shadow="alpha(black, 0.2)" inner-shadow-size=14 \
        border-gradient="@accent transparent @border" border-gradient-angle=70 border-width=1 \
        border-bottom="@border" border-bottom-width=2 \
        hover-bg="alpha(@accent, 0.05)"
}
layout { column gradient="@bg @rail" grain="alpha(@text, 0.05)" { … } }
PropriedadeO que faz
gradient="a b" ou "a b c"gradiente de 2 ou 3 cores (separadas por espaço)
gradient-angle=90graus: 0 da esquerda para a direita, 90 de cima para baixo (padrão)
pattern=dots|lines|grid|diagonalpadrão repetido; pede pattern-color
pattern-size=16 pattern-width=1distância entre repetições e espessura do traço (ou raio do ponto)
grain=corgrão: ruído fino, tingido por essa cor
vignette=cor vignette-size=0.55escurece (ou tinge) as bordas; size é onde começa, de 0 (centro) a 1 (cantos)
inner-shadow=cor inner-shadow-size=14sombra para dentro
border-gradient="a b c" border-gradient-angle= border-width=borda em gradiente
border-top=cor border-right= border-bottom= border-left=borda só naquele lado
border-top-width=2 (idem para os outros lados)espessura daquele lado (padrão: border-width, ou 1)
hover-bg=corfundo por cima quando o mouse está em cima, com transição
drop-shadow=cor drop-shadow-size=32 drop-shadow-y=10sombra macia e oca: não escurece o que está embaixo de um painel translúcido (o shadow= antigo escurece)
corners=left|right|top|bottomquais cantos o preenchimento arredonda: uma janela de dois painéis lado a lado
border=corborda inteira, para usar direto num nó (nos estilos, ela já existe)

Custo: gradiente de 2 cores são só vértices. Grão, padrão, vinheta e gradiente de 3 cores são texturas minúsculas geradas uma vez e repetidas: um quad por quadro, nada de ruído recalculado. Tema que não usa nada disso não passa por esse código.

Grão muito forte no escuro atrapalha mais do que no claro. Quando o valor precisa mudar com o modo, use estilos separados: styles mode=light { style "pagina" grain="alpha(@text, 0.07)" } e styles mode=dark { style "pagina" grain="alpha(@text, 0.025)" }. Um nó também pode aparecer só num modo: when=modo-claro, when=modo-escuro.

O label sem nada disso continua igual e no mesmo caminho de sempre. Efeitos desenham o texto mais vezes: guarde para títulos e wordmarks.

#Fundos procedurais

Vão como primeiro filho de um stack, atrás de todo o resto. São parados por padrão: gerados uma vez, ficam numa textura, e um tema parado não acorda o app.

kdl
layout {
    stack {
        starfield color="alpha(@muted, 0.75)" color2="alpha(@accent, 0.8)" density=1.1
        orbit center-x=0.73 center-y=0.4 rings=7 color="alpha(@accent, 0.4)" color2=accent
        column { … painéis … }
    }
}
ComponenteCoresPropriedades
starfieldcolor estrelas de longe, color2 as de pertodensity=1
orbitcolor as órbitas, color2 as luascenter-x=0.7 center-y=0.35 rings=6
auroracolor e color2, uma para cada cortina
dunescolor, color2, color3: colinas de trás para a frente (o céu é o gradient do nó em volta)
topographycolorlevels=14 (quantas curvas de nível)
radarcolor anéis, color2 a varreduracenter-x=0.5 center-y=0.5 rings=5

Todos aceitam seed= (outro desenho), e todos menos topography aceitam movimento: motion=#true, ou melhor motion="$opcao", para o usuário escolher, e motion-fps=10 (no máximo 15). O movimento só desloca a textura ou redesenha uma peça pequena, e para sozinho com "Reduzir movimento" e com a janela minimizada ou fora de foco.

A máscara é só forma: a cor vem na hora de desenhar. Trocar de modo ou de cor de destaque não gera nada de novo. Só orbit e radar dependem do tamanho, e são refeitos uma vez quando a janela para de mudar.

Contraste primeiro. Texto nunca fica direto sobre um fundo forte: ponha um painel translúcido no meio (gradient="alpha(@surface, 0.9) alpha(@surface, 0.76)") e confira nos dois modos. Use cores derivadas de tokens: @muted no escuro são estrelas claras, e no claro viram tinta sobre papel.

#Claro e escuro

Todo tema tem as duas versões. Blocos com mode= só valem num dos modos:

kdl
colors mode=dark  { bg "#0b0906"; text "#ffcf73" }
colors mode=light { bg "#f4efe2"; text "#2e2412" }
roles mode=light "#7a4a00" "#9c3f10"

Sem mode=, o bloco vale nos dois. Se o tema não definir o claro, ele é derivado da paleta (papel quase branco, tinta escura e destaque escurecido). No layout, cl-<token> e cd-<token> sobrescrevem uma cor só no claro ou só no escuro. O usuário escolhe em Configurações → Aparência (Escuro / Claro / Seguir o sistema), ou pela linha de comando: --mode claro.

#Opções do tema

Um tema pode oferecer chaves de liga/desliga, que aparecem em Configurações → Aparência:

kdl
options {
    option "crt" label="Efeito CRT" description="Linhas de varredura…" default=#true
    option "verde" label="Fósforo verde" default=#false
}

Formas de usar as opções:

OndeComo
esconder/mostrar um nócrt when=crt, tabs unless=compacto
propriedade booleanabanner="$banner", typing="$!digitando" (o ! inverte)
bloco de cores, cargos, estiloscolors mode=dark when=verde { … }
estilostyle "card" sheen="$brilho"

As escolhas ficam salvas por tema no settings.kdl: ~/.config/larpercord/settings.kdl no Linux, %APPDATA%\larpercord\settings.kdl no Windows.

#Cores personalizadas (sem editar o .kdl)

Em Configurações → Aparência → Cores do tema você pode trocar qualquer token de cor (bg, sidebar, text, accent, link, bubble-self…) e as oito cores de cargo por um hex livre. Vale só para o tema atual e o modo atual (escuro ou claro), e tem prioridade sobre a “Cor de destaque” global.

  • #RRGGBB para cor opaca; #RRGGBBAA para cor com transparência.
  • Clique num item da grade, cole o hex e aperte Enter.
  • “Limpar esta cor” volta aquele item ao tema; “Restaurar tema” apaga as escolhas do tema.
  • As escolhas ficam em settings.kdl como theme-colors "nome" mode=dark accent="#…", então não alteram o arquivo do tema.
  • Trechos que usam c-… fixo no layout (alguns temas usam para manter contraste) continuam com a cor do arquivo; para mudar esses, edite o .kdl.

#Em inglês

A interface tem português e inglês. Para o seu tema aparecer bem nos dois, ponha a versão em inglês ao lado: label-en= e description-en= nas opções, e description-en= no nó theme. Sem elas, aparece o texto em português.

kdl
theme "meu-tema" description="Servidores embaixo." description-en="Servers at the bottom."
options {
    option "crt" label="Efeito CRT" label-en="CRT effect" description="Linhas de varredura" description-en="Scanlines"
}

#Compartilhar seu tema

Temas prontos podem entrar na galeria da comunidade, onde qualquer pessoa vê a prévia ao vivo, abre no criador de temas ou baixa o .kdl. A galeria sai de themes/community/ neste repositório.

  1. Faça o tema no criador de temas, ou à mão. Na aba Arquivo do criador (ou clicando no nome do arquivo no topo), preencha o nome, o autor, uma descrição e a licença. "Pronto para a galeria da comunidade?", no fim dessa aba, mostra o que ainda falta.
  2. Baixe o .kdl em Exportar → Baixar .kdl. O arquivo leva o nome do tema: "Neon Dusk" vira neon-dusk.kdl.
  3. Faça um fork do repositório, coloque o arquivo em themes/community/ e abra um pull request. Um tema por pull request.

O nó theme leva os metadados:

kdl
theme "Neon Dusk" author="seu nome" description-en="Purple dusk over a dark city." description="Crepúsculo roxo sobre uma cidade escura." license="CC0-1.0" preview=classic
CampoRegra
nome (o primeiro argumento)até 48 caracteres. O nome do arquivo é o nome em minúsculas com hífens (neon-dusk.kdl)
author=seu nome ou apelido, até 80 caracteres
description-en= / description=pelo menos uma (inglês ou português), até 240 caracteres cada. As duas é melhor
license=uma licença aberta da lista abaixo, escrita como o identificador SPDX dela. O app ignora
preview=opcional, uma das miniaturas de Nós de topo

As licenças que a galeria aceita, sozinhas ou juntas com AND / OR (GPL-3.0-or-later OR MIT): CC0-1.0, CC-BY-4.0, CC-BY-SA-4.0, CC-BY-3.0, CC-BY-SA-3.0, MIT, MIT-0, ISC, 0BSD, BSD-2-Clause, BSD-3-Clause, Apache-2.0, MPL-2.0, Zlib, Unlicense, WTFPL, EUPL-1.2, GPL-2.0-only, GPL-2.0-or-later, GPL-3.0-only, GPL-3.0-or-later, LGPL-2.1-only, LGPL-2.1-or-later, LGPL-3.0-only, LGPL-3.0-or-later, AGPL-3.0-only e AGPL-3.0-or-later. Todas deixam usar e mudar o tema.

O que é conferido:

  • Ele tem de carregar no app. O python3 tools/gen_site.py lê cada arquivo de themes/community/ com as regras do app (sintaxe, tokens de cor, expressões de cor, nomes de componentes, os metadados acima) e para com arquivo:linha:coluna no primeiro problema, então um arquivo quebrado derruba o build do site. Depois, o node tools/theme_builder_test.js carrega cada tema com a cópia que o site tem do leitor de temas do app (docs/assets/site/theme-builder-core.js), nos dois modos e com todas as opções. O CI roda os dois em todo pull request. Dá para rodar a mesma checagem antes de mandar: python3 tools/gen_site.py --check-community (no Windows, py tools/gen_site.py --check-community). Para ver no app, coloque o arquivo na sua pasta de temas (a tabela no começo desta página), feche o larperCord se ele estiver aberto e abra com --theme neon-dusk.
  • Um nome só dele. Nem o nome de um tema embutido (um arquivo chamado orbital.kdl tomaria o lugar dele no app) nem um que já esteja na galeria. Um tema embutido só com o nome trocado volta: mude as cores ou o layout.
  • Sem logos nem fontes protegidos. Só arquivos .kdl entram na pasta, então nada de imagens ou arquivos de fonte. Não redesenhe o logo ou a marca de outra pessoa com label, shape ou arte em ASCII, e só cite fontes que dá para conseguir de graça. As fontes são procuradas no sistema de quem usa e nunca vão junto com o tema. No Linux, pela família, via fontconfig. No Windows, por um arquivo em C:\Windows\Fonts com o nome da família, ou senão Segoe UI, Consolas ou Georgia (Fontes no Windows), então confira se o seu tema continua bonito com elas.
  • Uma licença aberta da lista acima. Ela diz que as pessoas podem usar e mudar o tema. Se as cores vieram do tema de outra pessoa (pelo Abrir → "Cores de um tema do Discord" do criador, por exemplo), a licença daquele tema tem de deixar, e a descrição deve dar o crédito a quem fez.

#Dicas de design

O que separa um tema bonito de um tema estranho quase nunca é a cor de destaque. Normalmente é:

  • Um conceito só. "Caderno", "terminal", "portátil de 1989"… e tudo segue ele: cores, fonte, cantos e bordas.
  • Superfícies que se separam. Fundo, painéis e elementos elevados precisam de degraus de luminosidade claros. Roxo sobre roxo sobre roxo vira uma massa só.
  • Poucas cores acesas. Uma de destaque e, no máximo, uma secundária. Use roles com cores da mesma família para os nomes não virarem um arco-íris.
  • Uma fonte de texto, e no máximo uma de títulos (header … font="Liberation Serif").
  • Contraste suficiente para text, muted e faint sobre o fundo de cada painel. Use c-… quando um pedaço do layout tem fundo bem diferente (barra lateral escura num tema claro).
